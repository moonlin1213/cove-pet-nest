# 从 v0.1.0 升级到 v0.2.0

v0.2.0 沿用原数据目录，在启动时增加阶段历史、生活事件和图片任务字段。已有宠物 ID、种子、六维性格、成长值、阶段、粮仓、照顾回执、初始图片与凭据均保留。

1. 记下当前使用的 `PET_NEST_DATA_DIR`，先执行 `cove-pet-nest backup ./private-backup-before-v020`，备份目标必须不存在。
2. 停止小屋网页服务和连接它的 MCP 进程。保留旧安装环境、原数据目录和备份作为恢复材料。
3. 从仓库获取 `v0.2.0`，在虚拟环境重新安装 `pip install .`；也可以安装 GitHub Release 附带的 wheel。不要把源码目录下虚构的示例换成私人数据。
4. 设置原来的 `PET_NEST_DATA_DIR`。持续蜕变与生活照需要新增 `PET_NEST_IMAGE_EDIT_ENDPOINT`，见 [图片服务说明](images.md)。没有配置时等待配置，不发送无参考图的替代请求。
5. 重启 `cove-pet-nest serve` 与 MCP，在小屋确认宠物、粮仓和相册。

旧版没有记录每次外观启用的精确时间，也没有保存被替换过的所有初始图集。升级会把现有可用外观收进相册；已经孵化的神秘灵宠可补入通用蛋壳与当前模样，当前孵化日期标为估计值。不会声称恢复了旧版从未保存的图片。升级前的照顾回执继续保留，生活照片的事实记录从 v0.2.0 开始积累。

普通宠物及已孵化灵宠今后都可持续成长。已有足够成长与相处天数的宝宝可能在启动后立即准备下一阶段；成功后才切换，新图未就绪仍显示原图。除首次孵化外，需要参考图编辑接口。生活照片始终需要主动请求，不会因为打开相册或升级而自动生成。

若需回到 v0.1.0，请使用保留的旧环境，把升级前备份恢复到一个全新的数据目录，确认后再切换宿主配置。不要让两个版本同时写同一目录，也不要以旧版直接覆盖已升级目录；新增图片和记录应先单独保留。备份与恢复方法见 [备份说明](backup.md)。
